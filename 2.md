4. Cek `git log --all -p -- .env .env.example .env.local` untuk memastikan apakah benar-benar pernah ter-commit. Kalau iya, bersihkan history (`git filter-repo` atau BFG) **setelah** rotasi selesai, bukan sebelumnya.

# BAGIAN 1 — Isi `DOKU_ENABLED_METHODS`

Kode whitelist-nya sudah benar. Yang kurang cuma isinya.

**Cara menentukan isi — jangan menebak:**
1. Buka Doku Dashboard → `Transaction > Logs`. Cari request yang gagal, catat **error code aslinya** (pesan "Oops" hanya UI generic).
2. Uji satu per satu dengan nominal kecil di sandbox. Catat mana yang benar-benar sampai ke halaman pembayaran.
3. Isi env **hanya** dengan yang terbukti jalan:
   ```
   DOKU_ENABLED_METHODS=VIRTUAL_ACCOUNT_BCA,EMONEY_SHOPEEPAY
   ```

**Kalau ternyata tidak ada satu pun channel Doku yang jalan:** biarkan `DOKU_ENABLED_METHODS` kosong dan **sembunyikan kartu Doku sepenuhnya** dari FE (lihat Bagian 4). Lebih baik menampilkan satu metode yang berfungsi daripada dua metode yang salah satunya selalu error.

**Catatan:** `pro.md` memuat dua ejaan untuk ShopeePay (`EMONEY_SHOPEEPAY` dan `EMONEY_SHOPEE_PAY`). Konfirmasi ke Doku sebelum dipakai.

# BAGIAN 3 — Endpoint QRIS

## 3.1 — `POST /api/qris/create`

Ini yang membuat QRIS akhirnya muncul.

**Alur:**
1. Validasi input dengan `zod` — pakai skema yang sama dengan `api/checkout.ts`.
2. Cek whitelist beta dan kepemilikan produk — **logika identik** dengan `checkout.ts`. Ekstrak jadi `api/_lib/guards.ts` supaya tidak ada dua salinan yang bisa menyimpang.
3. Ambil `product` dari Supabase, hitung `baseAmount = product.price + SERVICE_FEE`.
4. Generate `orderRef` (format sama seperti sekarang).
5. `finalAmount = generateUniqueAmount(baseAmount, orderRef)`.
6. Insert order dengan `payment_method='qris'`, `qris_provider='self'`, `status='pending'`, `expires_at = now() + 30 menit`.
   **Kalau insert gagal karena unique index `final_amount`**, ulangi dengan `attempt+1`. Maksimal 5 percobaan, lalu balas `503` dengan pesan agar pembeli mencoba beberapa menit lagi.
7. `qrString = convertQRIS(process.env.QRIS_STATIC_PAYLOAD, { amount: finalAmount, billNumber: orderRef })`.
8. Kirim notifikasi Telegram ke admin.

**Response:**
```json
{
  "orderRef": "LCL-1756...",
  "qrString": "0002010102122669...",
  "finalAmount": 62317,
  "baseAmount": 62500,
  "uniqueSuffix": 317,
  "expiresAt": "2026-08-23T12:30:00.000Z"
}
```

**Jangan pernah** mengembalikan `QRIS_STATIC_PAYLOAD` mentah. Verifikasi juga bahwa variabel ini **tidak** berprefix `VITE_` — kalau iya, ia ikut ter-bundle ke browser.

**Guard startup:** kalau `QRIS_STATIC_PAYLOAD` kosong atau `validateQRIS()` menolaknya, balas `503` dengan pesan jelas di log. Jangan biarkan gagal dengan pesan membingungkan saat pembeli sedang menunggu.

## 3.2 — `POST /api/confirm-payment`

Terima `orderRef` + file bukti transfer (`image/*`, maks 5 MB). Kompres di sisi client ke maksimal 1600px sebelum dikirim. Upload ke bucket `payment-proofs`, set status → `awaiting_verification`, simpan `proof_url`, kirim notifikasi Telegram. **Idempotent** — dipanggil dua kali tidak boleh menggandakan apa pun.

## 3.3 — Perluas `GET /api/order-status`

Sekarang hanya mengembalikan `{ status }`. Ubah jadi:
```json
{ "status": "pending", "paymentMethod": "qris", "expiresAt": "...", "finalAmount": 62317 }
```
Tambahkan **auto-expire**: kalau `status='pending'` dan `expires_at < now()`, update ke `expired` sebelum merespons.

## 3.4 — Admin

- `POST /api/admin/verify` — `approve` / `reject`. Lindungi dengan `Authorization: Bearer ${ADMIN_TOKEN}`, bandingkan constant-time. Saat approve → panggil `settlePayment({ source: 'admin' })` yang sudah ada. **Jangan tulis ulang logika entitlement.**
- `POST /api/admin/reconcile` — terima teks mutasi mentah, ekstrak nominal, cocokkan ke order `awaiting_verification` dengan `final_amount` sama persis dan belum expired. Auto-approve hanya kalau cocok **tunggal**; kalau lebih dari satu, kembalikan daftarnya untuk dipilih manual.

# BAGIAN 4 — Frontend Terpadu

## 4.1 — `Checkout.tsx`: pemilih metode

Saat ini kotak amber "Pembayaran QRIS — INSTAN" menjanjikan QRIS padahal tidak ada tombolnya. **Ubah jadi pilihan yang benar-benar berfungsi.**

Di atas form Data Pembeli, tambahkan `RadioGroup` (sudah ada di `components/ui`) berisi dua kartu:

**Kartu 1 — QRIS** *(default, badge "Instan")*
- Pindahkan styling amber gradient yang sudah ada ke dalam kartu ini. **Jangan buat gaya baru** — konsistensi visualnya sudah bagus.
- Chip aplikasi: GoPay, OVO, DANA, ShopeePay, BCA, Mandiri, BRI, CIMB

**Kartu 2 — Transfer Bank / E-Wallet** *(via Doku)*
- **Hanya tampil kalau `DOKU_ENABLED_METHODS` tidak kosong.** Ambil flag ini dari `GET /api/pricing-config` (tambahkan field `dokuAvailable: boolean` — kirim boolean saja, jangan bocorkan daftar channelnya).
- Kalau kosong, kartu ini hilang dan QRIS jadi satu-satunya metode.

**Submit bercabang:**
```
qris → POST /api/qris/create → navigate('/payment/pending?orderRef=...')
doku → POST /api/checkout     → loadJokulCheckout(paymentUrl)
```

**Perbaiki race condition script Jokul.** Script dimuat `async` di `useEffect`; kalau pembeli submit cepat, `loadJokulCheckout` belum ada dan langsung fallback ke redirect. Simpan `Promise` yang resolve di `script.onload`, lalu `await` sebelum memanggil.

## 4.2 — `PaymentPending.tsx`: render bercabang

Ambil `paymentMethod` dari `/api/order-status`.

**`doku`** → pertahankan tampilan spinner yang sekarang; teksnya sudah tepat.

**`qris`** → render komponen baru `src/components/payment/QrisPayment.tsx`:

1. **Badge status** — pending (amber) / awaiting_verification (biru) / paid (hijau) / expired (abu)
2. **Countdown 30 menit** `MM:SS` + `Progress` bar. Habis → tombol "Buat ulang pesanan".
3. **QR canvas** via `qrcode`:
   ```
   errorCorrectionLevel: 'M'   ← JANGAN 'H'
   margin: 2, width: 320
   color: { dark: '#000000', light: '#FFFFFF' }
   ```
   **Aturan keras:** latar putih solid, isi hitam solid. Tanpa warna brand, gradient, atau logo di tengah — kamera aplikasi bank akan gagal membaca. Payload 251 karakter sudah cukup padat; ECC `H` akan membuat modulnya terlalu rapat. Logo boleh di **luar** area QR.
4. **Nominal unik** — besar, 3 digit terakhir diberi warna berbeda:
   > "Bayar **tepat** Rp 62.**317** — 3 angka terakhir adalah kode unik pesanan Anda. Nominal berbeda akan memperlambat verifikasi."
5. **Tombol:** Unduh QR (`canvas.toDataURL`), Salin Nominal (angka polos), Salin Kode QR
6. **Accordion panduan** scan per aplikasi
7. **"Saya Sudah Bayar"** → `Dialog` upload bukti → `POST /api/confirm-payment`
8. **Tombol WhatsApp** — deep link berisi `orderRef`, judul e-book, dan nominal, memakai `whatsappUrl` dari `@/data/stats.ts`

**Ganti polling manual** `setInterval(3000)` dengan `useQuery` dari `@tanstack/react-query` (sudah terpasang di `App.tsx`). Interval 3 detik selama 5 menit pertama, lalu turun ke 15 detik, berhenti otomatis saat status final.

## 4.3 — Mobile

Mayoritas pembeli membuka dari HP dan **tidak bisa scan QR di layarnya sendiri**. Pakai hook `use-mobile.tsx` yang sudah ada untuk menonjolkan tombol **"Simpan QR ke Galeri"**, dengan petunjuk: *"Simpan gambarnya, lalu buka aplikasi pembayaran → pilih 'Scan dari Galeri'."*

Ini bukan detail kecil. Tanpa ini, sebagian besar pembeli mobile akan menatap QR yang tidak bisa mereka pakai.

## 4.4 — Halaman admin

`/admin/orders` — token disimpan di `sessionStorage`. Tabel order, preview bukti transfer, tombol Approve/Reject, dan textarea untuk paste mutasi.
